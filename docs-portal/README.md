# WAP Labs Atlas

Astro-based project, planning, compliance, source, and document portal for WAP Labs.

The portal is a validated view over canonical repository artifacts. Do not copy planning or source
metadata into this package. Update the JSON manifests or active Markdown documents that already
own the information, validate them, then rebuild.

## Authoring and assembly boundary

Atlas uses four JSON inputs:

- `docs/waves/wap-1.2.1-compliance-program.json` is reviewed, handwritten planning content.
- `spec-processing/source-manifests/wap-1.2.1-release.json` is owned by the source-manifest lane.
- `spec-processing/source-manifests/wap-1.2.1-effective-spec.json` is generated by its named
  compliance generator and carries its canonical input path.
- `spec-processing/source-manifests/wap-1.2.1-selected-normative-clauses.json` is generated by its
  named compliance generator and carries generator, work-item, date, and redistribution
  provenance.

The JSON Schemas under `schemas/` describe the Atlas input contract. `src/lib/atlas-data.mjs`
validates schemas, enums, references, summary counts, and canonical ordering before Astro imports
any records. It also sorts the source catalog by document ID so page and route assembly is stable.
It does not rewrite, copy, or generate any canonical input.

Astro assembly is the only generation owned here. It renders ignored `dist/` files from validated
JSON plus handwritten active Markdown, and records the Astro version in each page's standard
`generator` metadata. Generated evidence inputs stay owned by their existing generators and
provenance rules.

## Run locally

```sh
pnpm install
pnpm dev
```

## Validate

```sh
pnpm --dir docs-portal run test:data
pnpm --dir docs-portal run check
pnpm --dir docs-portal run build
```

Run `test:data` while editing an Atlas input for fast, path-specific failures. Run `check` for the
same data gate plus Astro type checking. `build` always runs data validation before static assembly,
so Pages and release builds cannot bypass the contract.

When a deliberate input shape or enum changes, update the owning artifact and its Atlas schema in
the same change. Do not hand-edit generated compliance manifests; use their documented generator
and verification command. New cross-file references must point at an existing record, sprint
dependencies must point backward in program order, sprint work items remain ID-ordered, and
effective-spec families remain family-ID-ordered.

The static production build is emitted under ignored `dist/` with the configured `/wap-labs/atlas`
base. Running the build repeatedly from unchanged inputs must produce the same file inventory and
bytes.

The Pages workflow packages the three independent static applications together:

- marketing site at `/wap-labs/`;
- WaveNav simulator at `/wap-labs/simulator/`;
- project Atlas at `/wap-labs/atlas/`.

Run `make preview-pages-local` from the repository root to build and serve that complete layout.
